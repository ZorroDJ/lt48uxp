## Operator behavior

All entries have Read, Blank Check, Program, Overprogram, Verify, Compare and Erase. AT25DF and modern AT45DB also have Secure. RM24C and legacy AT45DB642 have seven operations; their selected source does not expose an applicable ordinary Secure operation.

- **AT25DF:** the main array uses normal NOR programming. Erase preserves the appended 64-byte OTP region. The original Secure procedure is **permanent sector lockdown**, checked independently for every 64-KiB sector. GTK warns that erase cannot undo it.
- **AT45DB:** page sizes include 264, 528 and 1056 bytes, plus the source's binary-page variants. Partial reads use encoded page/byte addresses. The streaming program applet starts at page zero, so Program/Overprogram require the complete main array or complete main-plus-security image. The source initialization applies the selected page-size setting; the operator must select the correct variant. Appended 64-byte security data is OTP and is preserved by erase. Secure changes reversible sector protection without adding new permanent lockdown bits. Program/Erase clear reversible protection before writing; existing permanent locks are preserved and cannot be bypassed.
- **RM24C:** rewrites are supported, including 0-to-1 changes. Erase writes FF through the source page-write procedure, including the writable ID page, with independent verification. These appear under the GUI's NVRAM/FRAM memory filter, rather than SPI flash.
- **Legacy AT45DB642:** 1056-byte pages, original parallel read and program-with-erase applets, full chip erase. The supplied package adapter remains required.

No hardware was accessed for this batch. A GUI preflight is a preparation check, not an electrical qualification.

## Native implementation

`c/src/addtab_spi.c` now handles these source-bound variants. Application execution is C; Python is used only for offline analysis and test orchestration. Original applets and FPGA images are still loaded from the operator's own matching REZ files.

Definition/family/pin-map/package/capacity tuples must match. The existing 1,138-entry SPI group keeps its separate admission list. Additional admission is generated by `tools/generate_adesto_admission.py` after the required execution reports pass; metadata extraction alone does not enable devices.

GDCA declares seven initially empty pin groups. Materializing them follows the original loader and fixes the 64-Mbit initialization failure. Missing logical pins in four initialization waves retain only the previously audited resident no-op behavior. RM24C32's duplicate read binding uses the final W48 binding, as the original loader does; see `DATAMAN_1310_HOST_ANALYSIS.md`.

### AT45DB642D parallel configuration correction

The source D26/M26/W8b protection reader ANDs buffer3 with F0 and then tests it against FF. It also differs from its sibling lockdown reader by consuming an extra byte before the 32-byte register traversal and using the saved byte for sector31. The native correction removes that extra read, tests the masked value against F0 and uses the current masked byte for sector31. Both register traversals now follow the documented first-sector-through-last-sector ordering.

The authored correction is in `NewDeviceLib/sources/adesto/at45db642d_config_read.inc`. It is compiled into C, is guarded by the exact source digest/definition/operation and expected byte patterns, and does not modify the imported REZ on disk. The unreachable comparison is recorded separately in `ORIGINAL_WINDOWS_SOFTWARE_BUGS.md`. The complete corrected traversal has offline execution evidence; physical qualification remains pending.

Manufacturer references: [AT45DB642D datasheet, section 9.1.3](https://www.mouser.com/datasheet/2/590/doc3542-541021.pdf), [AT25DF321A datasheet](https://www.renesas.com/en/document/dst/at25df321a-datasheet).

## Verification and limits

Evidence lives in `analysis/adesto-batch/`:

- `compiler-with-declared-defaults.json`: 143 entries; 342 unique native/reference compact compilations; 1,347 duplicate contexts reused; no unresolved comparisons. This compares the original waves; the deliberate W8b correction is additional.
- `at25-execution.json`: five definitions, native operations with unchanged 8051 applets, main/OTP boundaries, all sector-lockdown bits and rejection of ignored lockdown commands.
- `dataflash-execution.json`: twenty definitions; native C and unchanged 8051 applets, page-crossing reads, streaming writes, Verify/Compare, main-array erase and OTP preservation, protection/unprotection and ignored-protection rejection.
- `rram-execution.json`: four definitions; native rewrite/clear workflows across the first, second, last main and ID pages.
- `old-dataflash-execution.json`: original 40TS binding, page writes, boundary reads, Verify/Compare and full-array erase.
- `full-dataflash-program.json`: complete 135,232-byte native Program, including nontrivial OTP data, verification and fresh-session readback.
- `registry-test.log` and `gui-test.log`: production support admission and actual GTK preflight/filter checks.

The serial/parallel device models supply external bus data, completion and timing inputs. Original 8051 handlers execute unmodified; large sequential reads are accelerated after executing their initial handler. These tests establish source selection, addressing, protocol and host-workflow behavior under those modeled inputs. They do not prove physical voltages, signal integrity, adapter wiring, or that every original bitstream is electrically correct on every hardware revision. Hardware qualification stays separately marked.
